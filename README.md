# umikke Backend - 漁場予測AIシステム API・推論エンジン

本リポジトリは、環境DNA（eDNA）と海洋環境データを用いて漁場を予測するシステム「umikke」のバックエンドリポジトリです。
フロントエンドと連携するためのREST APIサーバーとしての機能と、深層学習モデルを用いた空間予測エンジンの機能を担っています。

審査員の方々に特にご覧いただきたい、本システムの中核となる実装上の工夫は以下の3点です。

### 1. ConvLSTMを用いた時系列・空間AI予測 (`infer_and_export.py`)
単純な数値の回帰ではなく、海洋環境の「空間的な変化」と「時間的な変化」を同時に捉えるため、**Seq2Seq型 ConvLSTM (Convolutional LSTM)** をモデルとして採用・実装しました。
* 過去14日間の海洋環境データ（海面水温・クロロフィル・光合成有効放射）の画像テンソルを入力として受け取り、未来60日分のeDNA分布ヒートマップを生成します。
* 処理負荷を軽減するため、陸地部分を動的に除外するマスク処理を取り入れ、対象となる海域のみの推論にリソースを集中させる工夫をしています。

### 2. データパイプラインの完全自動化 (`main_pipeline.py`)
システムを実際の運用に耐えうるものにするため、バッチ処理のパイプラインを構築しました。
1. `env_csv_save.py` : 大量の海況CSVデータを一括でデータベースに高速インポート
2. `infer_and_export.py` : 最新の環境データに基づき、AIによる推論とヒートマップ画像の出力
3. `generate_hotpoints.py` : 予測結果から、閾値（スコア0.8以上）を超える有望な漁場（Hotpoint）を自動抽出しDBへ登録

これを定期実行することで、常に最新の予測データがシステム全体に反映される設計にしています。

### 3. FastAPIとPydanticを用いた堅牢なAPI設計
フロントエンドからの多種多様なリクエストに対し、高速かつ安全に応答するため FastAPI を用いてAPIを構築しました。
* `schemas.py` において Pydantic モデルを定義し、厳密な型定義とバリデーションを実施しています。
* ユーザー管理、魚種データ、海洋データといった機能ごとにルーティングを分割 (`routers/` ディレクトリ) し、チーム開発においてコンフリクトが起きにくい、見通しの良いディレクトリ構成を実現しています。

```text
.

├── main_pipeline.py         # AI推論・データ処理の自動化パイプライン（バッチ処理）
├── infer_and_export.py      # 【注目】ConvLSTMによるeDNA分布予測の推論ロジック
├── generate_hotpoints.py    # 予測結果からのHotpoint自動抽出ロジック
├── convlstm_op_final.pth    # 学習済みのConvLSTMモデル重みデータ
├── routers/                 # 各機能のAPIエンドポイント
│   ├── users.py             # ユーザー認証・グループ管理API
│   ├── fish.py              # 魚種データ・Hotpoint・eDNAデータAPI
│   └── ocean.py             # 海洋環境データ取得API
├── database.py              # データベース接続設定 (SQLAlchemy)
├── models.py                # データベースのテーブル定義 (ORM)
├── schemas.py               # APIのリクエスト/レスポンススキーマ (Pydantic)
├── crud.py                  # データベースに対するCRUD操作ロジック

├── edna_save.py             # eDNA推論結果の正規化・クリーンアップ処理
├── CSV/                     # 入力・出力用の各種CSVデータ
